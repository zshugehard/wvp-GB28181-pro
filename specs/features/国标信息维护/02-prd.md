## 2. 用户旅程

1. 管理员进入“系统设置 → 国标服务配置”。
2. 页面加载当前生效配置，国标编号、国标域、认证密码均回显当前值；国标域为空且 id 有效时默认显示 id 前 10 位；密码可见但可切换隐藏。
3. 管理员修改国标编号时，若国标域为空或仍等于旧 id 前 10 位，则自动填充为当前 id 前 10 位；管理员手工修改国标域后，不再自动覆盖，且允许与 id 前 10 位不同。
4. 管理员修改国标编号、国标域或密码，前端即时校验格式；密码为空时不允许保存。
5. 点击保存，后端再次校验；校验失败时不写盘、不改运行时值，并返回明确字段错误。
6. 校验通过后先原子写 YAML，再一次性更新运行时身份；成功响应明确告知“身份字段已对后续请求生效”，已建立的注册/Dialog 不被主动注销。
7. 若同时修改端口/IP 等绑定字段，响应仍提示这些字段需要重启；页面用重启标签区分两类字段。
8. 管理员重新打开页面，看到刚保存的明文密码与新的 ID/域。

## 3. 切片验收

> **任务粒度（2026-11-11 评审批注）**：本胶囊是单一端到端交付任务，不拆分 Story。下列 AC-1~AC-7 是同一任务的验收边界，不能作为可独立交付或独立排期的切片；保留分项只为让验收可逐条核验。

### AC-1 页面可编辑与回显

- 页面存在国标编号、国标域、认证密码三个可编辑字段。
- 查询接口返回当前 YAML 中的明文密码；页面初始值等于该密码。
- 密码输入框提供显隐切换，默认不自动隐藏到无法核对。

### AC-2 格式校验

| 字段 | 规则 | 失败表现 |
|---|---|---|
| 国标编号 `id` | 必填；去除首尾空白后必须匹配 `^\d{20}$` | 400；字段错误“国标编号必须为20位数字”；不写盘 |
| 国标域 `domain` | 必填；去除首尾空白后必须匹配 `^\d{10}$`；默认自动填充为 id 前 10 位，但允许用户改成不同值；不要求等于 id 前 10 位 | 400；字段错误“国标域必须为10位数字”；不写盘 |
| 认证密码 `password` | 必填；空字符串或仅空白拒绝保存；非空时原样保存，不 trim、不转义、不哈希 | 400；字段错误“认证密码不能为空”；不写盘 |

> `domain` 只冻结 10 位数字格式，不冻结与 `id` 前 10 位的强一致关系；默认填充是输入便利，不是保存约束。

### AC-3 明文保存与回显

- YAML 中 `sip.password` 保持明文。
- 查询接口返回明文密码，不使用 `******` 哨兵。
- 保存后重新查询，返回值与提交值逐字符一致（包括空格、符号）。
- 空密码不会进入保存成功路径，因此不会把现有密码清空或切换为“禁用公共密码”状态。

### AC-4 保存后仅后续请求使用新配置

- 保存成功后，新的 `id`、`domain`、`password` 对后续新的 SIP 请求/事件可见。
- 验证点至少包括：注册鉴权读取新密码与新 domain；SIP From/To 使用新 id/domain；SSRC/分组编码使用新 domain。
- 已建立的注册与 Dialog 不被主动注销，也不要求立即重新校验；设备后续请求若仍使用旧密码，可能在下一次鉴权时失败，但系统不主动踢下线。
- UI 与 ADR 必须区分“后续请求生效”和“立即断开旧会话”，不得使用“立即全部生效”这类歧义文案。

### AC-5 原子性与失败回滚

- 校验失败：YAML 与运行时值都不变。
- 写盘失败：运行时值不变，接口返回失败。
- 写盘成功但运行时更新失败：接口返回失败；YAML 已是新值，下一次重启会收敛到新值；不得返回“已生效”。
- 并发保存：最终 YAML 与运行时身份来自同一次成功提交，不得出现 id/domain/password 交叉组合。

> 上述失败路径的补偿、回滚、异常映射与并发实现由实现阶段决定；用户可感知要求只有“失败不得谎报已生效、配置最终可收敛”。

### AC-6 绑定字段保持重启语义

- `port`、`ip`、`showIp`、`timeout`、`alarm` 仍在 `restartRequiredFields` 中。
- 保存响应区分“已即时生效字段”与“需重启字段”。
- 不自动重启服务；保留现有“仅保存 / 保存并重启”用户选择。

### AC-7 国标域默认填充与弱一致

- 页面加载时若 domain 为空且 id 为有效 20 位数字，domain 默认显示 id 前 10 位。
- 编辑 id 时，若 domain 为空或仍等于旧 id 前 10 位，domain 自动更新为当前 id 前 10 位。
- 管理员手工修改 domain 后，后续 id 变化不得自动覆盖该值。
- 保存时只校验 domain 为 10 位数字；与 id 前 10 位不同不构成错误。

## 4. 承重假设

| 假设 | 失败后果 | 验证方式 |
|---|---|---|
| 所有 SIP 身份读取都经过单例 `SipConfig`，没有第二份启动期拷贝 | 热更新只改到部分路径，出现“页面显示新值、SIP 仍用旧值” | `rg "sipConfig\\.get(Id|Domain|Password)"` 全量审计；契约测试覆盖注册、From/To、SSRC |
| YAML 写入成功后，运行时 setter 不会抛异常 | 需要补偿或回滚设计 | 单测用 mock 强制 setter 失败；断言响应失败且不谎报生效 |
| 现有配置写入器能保留注释与其他配置项 | 保存会破坏用户配置 | 复用现有 `saveSipServerConfig_updatesValuesAndKeepsComments` 并扩展断言 |
| 密码明文回显是产品明确要求，不是安全缺陷 | 评审会要求脱敏，导致需求无法验收 | ADR-0008 明确记录；安全风险登记为后续议题 |
| 修改密码后不主动踢下线、既有会话不立即重校验（已确认） | 旧注册在自然过期前仍可通信，形成安全窗口 | ADR 明确边界；用户已确认接受；若未来要求强失效，另开切片 |
| 空密码拒绝保存不会破坏既有部署 | 现有空密码配置在保存其它字段前必须先填写密码 | 页面加载回显空值并提示必填；错误信息指向密码字段；不静默改写 YAML |
| domain 默认填充不会覆盖用户意图 | 管理员手工设置的非前缀 domain 被 id 编辑覆盖 | 仅在 domain 为空或仍跟随旧 id 前缀时填充；手工值保持不变 |

## 5. 非目标

- 不实现 SIP Stack 热重建。
- 不实现多租户或按设备覆盖公共密码。
- 不实现密码加密存储、审计日志或密钥轮换。
- 不实现通过清空密码禁用公共密码；空密码保存请求被拒绝。
- 不修改 GB28181 协议行为、SIP 端口或媒体服务器配置。
- 不新增第二份产品 PRD 或平行需求文档。
