## 2. 方案对比

### 方案 A：只写 YAML，保存后自动重启（否决）

- 优点：复用现有 `IApplicationRestartService`，实现最少。
- 否决理由：
  - 重启会中断所有正在播放、录像、级联和注册会话，代价远大于修改三个身份字段。
  - 前端已提供“仅保存 / 保存并重启”选择，自动重启会破坏用户控制权。
  - 不能证明“保存后立即生效”是字段级语义，只是把重启包装成保存。

### 方案 B：每次保存重建整个 SIP Stack（否决）

- 优点：对 `ip`、`port`、`showIp` 等绑定字段也能立即生效。
- 否决理由：
  - 需要停止并重建 `SipLayer` 的 TCP/UDP 监听点，已建立的 SIP 事务、Dialog、心跳和媒体会话都受影响。
  - 失败回滚复杂：新端口可能已被占用，旧监听点无法保证恢复。
  - 超出本次“编辑国标 ID、国标域、密码”的范围，属于第 4 套生命周期兜底。

### 方案 C：身份字段热更新 + 绑定字段保留重启（采用）

- 只把 `id`、`domain`、`password` 三个身份字段写入运行中的 `SipConfig` 单例；其余字段继续走现有 YAML + 重启路径。
- 保存流程按“校验 → 写 YAML → 热更新运行时字段”推进；校验失败时不得写盘或改运行时值。写盘成功但运行时更新失败时，接口必须返回失败且不得谎报“已生效”；具体补偿、回滚、写入原子性与并发同步策略由实现阶段决定，不向需求人员提问。
- 查询响应继续返回明文密码，前端使用可切换显隐的输入框回显；不引入掩码哨兵值，避免把“未修改”与“清空密码”混为一谈。

## 3. 关键取舍

1. **国标域：只校验格式，不强制与国标编号前缀一致**
   - 产品效果：页面默认用国标编号前 10 位自动填充国标域，减少输入；管理员随后可手工改成任意 10 位数字，保存时不会因与 id 前 10 位不同而报错。
   - 代码事实：当前前端 `validDomain` 仅做 `^\d{10}$` 校验且允许空值、后端 `validateSipServerConfig` 同样只校验非空值的格式；当前页面没有自动填充 watcher。
   - 技术决策：新增前端“仅在用户未修改 domain 时跟随 id 前 10 位”的填充效果；后端把 domain 改为必填且必须 `^\d{10}$`，但不加 `id.substring(0,10)` 等值断言。
   - 校验失败的可感知效果：domain 空、含非数字或不足/超过 10 位时不允许保存，页面给出字段级错误；合法但与 id 前缀不同则允许保存。

2. **密码：空值拒绝，非空明文保存并回显**
   - 产品效果：管理员不能保存空密码；密码按原文保存、查询接口按原文返回、页面可核对当前密码（可切换显隐）。
   - 代码事实：当前 `validateSipServerConfig` 完全不校验 `password`；`saveSipServerConfig` 仅在 `password != null` 时写入 YAML；`RegisterRequestProcessor:168`/`:257` 把空公共密码解释为“禁用公共密码”。
   - 技术决策：保存入口对 `null`、空串、全空白（按产品可感知的“空密码”）统一拒绝；非空值不 trim、不哈希、不掩码；退役“空密码=禁用公共密码”的页面保存入口契约（保存路径不再产生空密码）；`RegisterRequestProcessor` 中“空公共密码=禁用”的运行时读取分支保留为既有读取语义，避免同一输入在保存与运行两条路径出现两套可写入解释。是否 trim 非空密码属于实现取舍，本胶囊按逐字符保存冻结，不追加底层问题。
   - 校验失败的可感知效果：密码为空时保存被拒绝并显示明确字段错误，配置文件与运行值都不改变。

3. **三个字段作为一个原子身份组提交**
   - 不允许只更新 `id` 不更新 `domain` 的中间态对外可见。
   - 校验在写盘前完成；写盘成功后一次性设置三个运行时值，并用 `volatile` 或等效的同步边界保证请求线程看到完整组合。

4. **密码明文是显式产品要求，不做假掩码**
   - YAML 中保持明文，查询接口返回明文，页面可回显。
   - 不把密码改成哈希：SIP Digest 鉴权需要原始共享密钥，哈希无法参与 `doAuthenticatePlainTextPassword`。
   - 不返回 `******` 占位符：那会让用户无法判断当前密码，也会让“保存未修改”覆盖真实密码。

5. **“后续请求使用新配置”边界（已由用户确认）**
   - 保存成功后，新注册、重新注册、INVITE、MESSAGE、SSRC 生成、分组编码等后续读取都使用新的 `SipConfig` 值；既有会话不要求立即重新校验。
   - 修改密码不主动注销已注册设备；已经完成鉴权的长连接注册、Dialog 继续保留，直到其自然过期或设备自行重新注册。
   - 代码事实：`RegisterRequestProcessor` 只在收到注册/注销请求时读取密码与 domain；`SipLayer` 不在保存路径重建监听或注销会话。
   - 该边界写入 UI 提示与 ADR，避免把“后续请求生效”误解为“立即断开所有旧会话”。

6. **端口、监听 IP、对外展示 IP 与超时/告警阈值不热更新**
   - `port`、`ip`、`showIp` 绑定到 `SipLayer` 的监听点和 SIP Stack，运行中修改无法安全生效；`timeout`、`alarm` 同样保留重启语义。
   - 五个字段继续由 `restartRequiredFields` 标识，保存后提示重启；不得把它们伪装成热字段。

7. **保留现有配置写入器，不新增第二套 YAML 编辑器**
   - 复用 `readConfigLines` / `setYamlScalar` / `writeConfigLines`，只把身份字段的运行时应用接在写盘成功之后。
   - 反熵增：不新增 `SipIdentityManager` 之类与 `SipConfig` 平行的第二真相源。

## 4. 风险与缓解

| 风险 | 触发条件 | 缓解 |
|---|---|---|
| 写盘成功、内存更新失败 | JVM 异常、字段 setter 异常 | 先完成所有校验与不可变快照；热更新阶段只做三个 setter，失败时记录错误并返回非成功；下次重启仍会从 YAML 恢复正确值 |
| 并发请求读到半更新身份 | 保存线程逐字段 setter | 使用一个不可变 `SipIdentity` 快照整体替换，或对三个字段的读取/写入使用同一把锁；契约测试覆盖 |
| 修改 domain 导致设备重新注册失败 | 设备侧仍使用旧 domain 计算 Digest | UI 明确提示“新注册/重新注册生效”；ADR 记录兼容边界；不自动踢设备 |
| 密码明文泄露 | 配置文件权限、接口响应、浏览器缓存 | 本次按需求保留明文；配置目录沿用现有文件权限；接口仍要求登录；在 ADR 的“不做什么”中登记后续加密/脱敏议题 |
| 现有测试断言全部字段需重启 | `SettingServiceImplTest:702` 的字段清单断言 | 将断言收窄为“仅 port/ip/showIp/timeout/alarm 需重启”，并新增身份字段热更新测试；用例只增不减 |
| 空密码旧语义仍存在于注册路径 | `RegisterRequestProcessor:168`、`:257` 把空公共密码视为禁用 | 保存入口拒绝空密码，退役页面保存入口契约；运行时读取分支保留，不新增第二套兜底解释 |
| 默认填充覆盖用户修改 | 管理员手工改 domain 后继续编辑 id | 填充规则只在用户未手工修改 domain 时生效；手工值不得被自动覆盖 |

## 6. 反熵增与退役

- 不新增与 `SipConfig` 并行的身份缓存。
- 不保留“保存后无条件提示重启”的旧文案；身份字段改为“已即时生效”，绑定字段仍提示重启。
- 不保留前端重复的格式校验作为唯一防线；前后端共享同一组规则语义，后端为最终权威。
- 不保留“空密码允许保存并触发禁用公共密码”的页面保存入口契约；删除其文档与提示，不在新校验旁再叠一层解释。运行时读取分支保留，不作为保存路径的写入来源。
- 不保留“domain 必须等于 id 前 10 位”的推测规则；自动填充仅作为减少输入的默认值。
- 不删除现有测试；只更新与新增，确保用例只增不减。
